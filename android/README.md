# DABplay+ Android app

Gradle multi-module project (see `../docs/architecture.md`). minSdk 26, compileSdk 37, targetSdk 36; AGP 9.4,
Kotlin 2.4, Compose. Builds with the installed JDK 25 (no Android Studio needed).

| Module | Kind | Contents |
|---|---|---|
| `dab-core` | Kotlin/JVM | DAB stack, ported from `../tools/` with golden tests: CRCs, `fic.FicDecoder` (FIG 0/0,1,2,6,9,13,21,24, 1/0,1), `dabplus.ReedSolomon` + `SuperframeDecoder` + `Asc`, `pad.PadDecoder` (DLS, DL+, MOT slideshow), `pad.DlsParser` ("Artist – Title" rules) |
| `tuner-api` | Kotlin/JVM | `DabTuner` interface, `Transport` (raw bulk USB), results/signal types |
| `driver-dtr100` | Kotlin/JVM | 16c0:05dc family driver over `Transport`: full port of `tools/dtr100.py` (init, clock plans, full tune, FIC, audio start/stop for fw ≤1/2–4/≥5, MSC, quality); tables generated by `../tools/gen_kotlin_tables.py`. Transfer-level golden test replays a real USB session log |
| `logos` | Kotlin/JVM | RadioDNS names (so far); SPI, manifest icons, radio-browser |
| `usb-android` | Android lib | `Transport` over `UsbDeviceConnection.bulkTransfer` |
| `audio` | Android lib | MediaCodec AAC decoder choice (FDK by name); MP2 decoder to come |
| `data` | Android lib | station model (`ServiceKey` = ECC + SId); Room/DataStore to come |
| `app` | Android app | Compose UI (Home, Stations, Now playing, Recent, Settings) from the Claude Design export (kept locally, not in the repo), engine, Media3 service |

```
cd android
echo "sdk.dir=$HOME/.local/opt/android-sdk" > local.properties    # once
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew test assembleDebug
```

Judge smoothness only on a **release** build: debug Compose is unoptimised and janks by design. The release build is
R8-minified and, for now, signed with the debug key (local testing only; no upload key yet):
```
JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell cmd package compile -m speed-profile -f io.github.jvspier.dabplay   # what Play does with baseline profiles
adb shell dumpsys gfxinfo io.github.jvspier.dabplay reset   # then interact, and read it back without "reset"
```

Emulator that mimics the head unit: AVD `dab-headunit-api29` (1280×720, 160 dpi, landscape), started with
`emulator -avd dab-headunit-api29 -no-window -no-audio -no-boot-anim -gpu host -no-snapshot`, then
`adb install -r app/build/outputs/apk/debug/app-debug.apk`.

Golden tests: `../tools/golden.py` writes `../captures/golden/*.txt` from the Python PoC for every capture in
`../captures/raw`; the `dab-core` tests reproduce them line by line (FIC content, every AU, every DLS change and
slide). Captures and goldens are local test material (gitignored); the tests skip when they're absent.

Testing the app with the real dongle in the emulator (no recordings are bundled; there is deliberately no replay driver):
- The API 26/29 emulator kernels can't host a full-speed USB device (EHCI only, no OHCI/UHCI/xHCI). Use the API 34
  image, AVD `dab-headunit-api34` (1280×720), with xHCI passthrough.
- Emulator images don't declare `android.hardware.usb.host` (real head units do). Once per AVD: boot with
  `-writable-system`, `adb root && adb remount`, reboot, `adb root && adb remount`, push
  `<permissions><feature name="android.hardware.usb.host"/></permissions>` to
  `/system/etc/permissions/android.hardware.usb.host.xml`, reboot. Keep using `-writable-system` afterwards.
- Start: `emulator -avd dab-headunit-api34 -gpu host -no-snapshot -writable-system -qemu -device qemu-xhci,id=xhci -device usb-host,bus=xhci.0,vendorid=0x16c0,productid=0x05dc`
